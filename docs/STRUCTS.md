# Typed struct views (`Generated/Structs`, assembly `Trw.Structs`)

Generated by `tools/regen.ps1 -StructViews` (generator: `tools/Trw.Transpile/StructViews.cs`, design: docs/TRANSPILER.md, "Struct views").
Guest memory stays one flat byte array (`Mem`); a view is a `readonly struct` holding only the guest address `P`, so it costs nothing at run time
(the accessors are inlined to the same `Mem.S32(P + 0x14u)` the old output had). Do not edit the files, they carry a header saying so.

## Naming rules
* One type per C struct/union/typedef, named as in the C sources (`OSThread`, `Actor`). Typedefs of anonymous structs take the typedef name; unnamed nested records are `Parent_field`.
* Members keep the C name. C# keywords get an `@` prefix (`@object`); names that clash with the view API (`P`, `IsNull`, `At`, `SizeOf`, `Set`, `Add`, ...) get a trailing `_`.
* Pointer members: `Foo next` (typed view) when the pointee has one layout, plus `uint next_` (raw address); scalar pointers are `S32Ptr`/`F32Ptr`/... (Trw.Platform/Views.cs); function and void pointers are `uint`.
* Every writable member has a setter method `x_Set(v)` too, because C# forbids property setters on a struct rvalue (`new Foo(p).next.x = 1` does not compile). Arrays: `arr[i]`, `arr.Set(i, v)`, `Length`, `Stride`.
* The decompiled headers are module-local, so one C name can have several layouts. The layout used by most translation units keeps the plain name; the others are `Name_v2`, `Name_v3`, ... (numbering is by the number of translation units using a layout, ties by layout fingerprint,
  so it is stable between regenerations of the same C). The emitter chooses the variant whose layout fingerprint equals the one of its translation unit. Per-function pseudo-structs of the decompiler
  (`SharedPlayer_func_80220D44_de`, `..._viewNN_M`) are views like any other. Structs with an unresolved field type or a bitfield have no view and stay `Mem.*`.
* Files: `StructsNN.cs` (120 structs each) and `ArrayViews.cs` (shared array types such as `F32x3`).

## Using views by hand (non-generated code, e.g. `src/Trw.Game/Os`, `Window`)
```csharp
using Trw.Game;                       // the views live in namespace Trw.Game (assembly Trw.Structs, referenced by Trw.Game)
var t = new OSThread(threadAddr);     // or (OSThread)threadAddr; implicit conversion back to uint
int id = t.id;                        // was Mem.S32(threadAddr + 0x14)
t.priority_Set(10);                   // was Mem.Set(threadAddr + 0x4, 10)
uint next = t.next_;                  // raw pointer;  t.next is the same address as an OSThread view
if (!t.next.IsNull) id = t.next.id;   // pointer chain, no address arithmetic
var third = new OSThread(arrayBase).At(2);   // element of an array of structs
```
Offsets and sizes come from the clang AST of the C port (MIPS o32), the same data the transpiler uses, so they cannot drift from the generated code. `SizeOf` is a constant.
Hand-written code can keep using `Mem.*` with its own constants; views are optional and can be adopted file by file.
